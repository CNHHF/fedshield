# 从商家材料生成业务配置

入口：规则引擎配置 → 业务智能配置。

1. 填写准备开展业务的国家/地区，粘贴业务介绍、收付款说明、客户类型及数据处理材料。也可逐个添加TXT、CSV、DOCX、文本型PDF；每个文件不超过2MB，合并文本最多30,000字。扫描件需先识别文字。
2. 点击“分析业务并配置”。系统调用已配置的DeepSeek服务，隐藏电话、邮箱和密钥格式后发送；其他业务文本仍会交给该服务。请使用有权处理的材料。
3. 查看业务事实及原文依据。经营市场和数据处理目的地分别提取，例如在德国销售、将数据传回中国，对应市场EU、数据目的地CN。缺少经营内容、数据类型或处理地点时须补充；合同效力、云商身份等列为后续人工核查。
4. 检查整组规则、条件和动作。数值与阻断条件须逐条确认；原文引用只帮助核对，不保证模型没有理解错误。参考资料限服务端已核验链接，不能把项目建议说成法定标准。
5. 点击“试跑样本”，填写金额、原币种及材料登记状态，对照当前设置与材料齐全的示例。示例不是实际订单，不执行交易、不发布统计、不扣预算。保存前试跑当前勾选集合；保存后读取当前数据库规则内容试跑。
6. 一次保存所选规则，默认禁用。在下方规则列表检查、编辑并启用需要的规则。预览画布不能绕过业务方案确认直接另存；编辑已保存的业务规则会再次要求确认。
7. 工作台选择数据流转目的地，再选择对应“业务规则方案”。下拉项显示启用数量；尚未启用任何规则的方案不可选。创建流程时校验账号和地区，执行时仅绑定此方案的规则生效。原有通用门禁仍保留。

最近20份分析可在业务智能配置顶部继续打开，原始材料及方案加密存储在`fs_business_configuration`表。仅当前账号可读取；其他账号不能查看、修改、启用对应业务规则。已有历史规则继续保留。

## 示例（虚构业务，用于功能演示）

目标：德国，面向个人消费者销售家居用品。

材料可直接写：

> 我们是中国的家居用品销售公司，准备在德国独立站销售普通家居用品，交易以EUR结算，通常50至300欧元。我们控制客户数据，德国网站收集订单、姓名、邮箱和收货地址，先存德国云服务，再传回中国用于履约和售后，不处理银行卡、健康或生物识别数据。以履行订单合同作为处理依据。传回中国前须登记处理依据和适用传输机制，未登记则要求补充材料。超过5000欧元的单笔订单需要补充人工核查记录，不直接认定欺诈。

已真实调用模型验证该类材料可生成4条规则，并区分材料缺失与齐全的试跑结果。金额规则明确限定EUR，不将5000欧元阈值套用到GBP公开订单。当前公开UCI数据是匿名英国零售订单；不能冒充该虚构德国商家订单。

## 接口

- `POST /api/compliance/business/extract`：multipart文件转文本。
- `POST /api/compliance/business/analyze`：materials、destination、answers，返回带原文依据的方案。
- `GET /api/compliance/business/history`：当前账号最近分析。
- `GET /api/compliance/business/plans/<id>`：当前账号方案及加密保存后解密返回的输入。
- `POST .../simulate`：contexts和ruleIds，最多20例；已保存方案试跑当前数据库规则。
- `POST .../apply`：confirmed=true、ruleIds、confirmedRuleIds，事务保存禁用规则组，重复请求不重复创建。
- `GET /api/compliance/business/plans`：当前账号已保存方案，供工作台绑定。

方案不自动判断合同有效、商品准入、税务、牌照或欺诈，也不执行真实付款。地区专项资料尚未接入的场景只提供项目与业务建议；正式使用需由有权人员确认适用性。生成失败最多进行一次结构修正请求，不以固定模板冒充模型输出。
