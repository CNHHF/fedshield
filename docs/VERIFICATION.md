## 四、验证过程中发现并修复的真实缺陷

以下问题均由上述验证真实触发后发现，而非事后人工检查（其中 4 项会导致服务无法使用）：

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | `seed.py` 调用 `RANDOM.lognormal()`（`random.Random` 无此方法，应为 `lognormvariate`） | **`python run.py` 启动即崩溃，后端起不来**；前端代理报 500「Request failed with status code 500」 | 改用 `lognormvariate` |
| 2 | `utils/deps.py` 读取 `AuditLog.region`，但审计日志表没有该列（登录地区存在 `node`） | **用户第二次登录必报 500**（第一次登录后产生了审计记录，风险评分即崩溃） | 改读 `AuditLog.node`，并用 `getattr` 兜底 |
| 3 | `PROPAGATE_EXCEPTIONS = True` | 异常被 Flask 直接抛出，前端只看到 HTML 500 → 通用报错，无法定位 | 关闭穿透，由全局处理器返回统一 JSON；前端对非 JSON 错误体也给出可操作提示 |
| 4 | `reset_all()` 未清理任务/审计/区块/授权记录等表 | 「重置」后残留历史数据 | 补全全部业务表并按外键顺序删除 |
| 5 | `/api/audit/chain/verify` 权限只给监管端与管理员，但导航栏每次进页面都会调用 | 普通用户每次进页面弹「权限不足」 | 运营端补该权限点；请求封装支持 `silent` 静默调用 |
| 6 | 匿踪查询索引按「清单集合」缓存，而预热用的是全量清单、查询用子集 | 缓存永不命中，首次查询 470~500ms，超出 ≤300ms 指标 | 改为**按清单名分片缓存**，并在服务启动/灌数后预热 → 实测 **5.29ms** |
| 7 | SM4 固定参数 CK 表被错误展平为 128 个字节值 | 加密结果不符合国密标准 | 按 32 位字打包，已通过 GB/T 32907-2016 两个官方向量 |
| 8 | PSI 客户端以「签名值」为键查盲化表 | 隐私求交必然抛异常 | 按请求顺序保存 `(b, r, h)` 并校验签名 `s^e ≡ b` |
| 9 | 联邦聚合中各节点使用各自的量化 scale，聚合方按第一个节点的 scale 还原 | 全局模型数值错误 | 全体节点共用公共量化尺度 |
| 10 | Top-K 剪枝未命中参数被永久冻结在 0 | 模型无法收敛（AUC 0.72） | 首次稠密预热轮 + 未传输参数沿用上一轮全局值 |
| 11 | 差分隐私敏感度手工取 1.0，噪声远大于参数本身 | 模型被噪声淹没 | 由 DP-SGD 逐样本梯度裁剪推导敏感度上界 |
| 12 | 规则引擎把「条件命中的阻断动作」判为 passed | **合规阻断失效**（P1 未授权出境被判为通过） | 重写判定语义：命中+block→blocked，命中+require/mask→failed |
| 13 | 法规库仅 178 条，未达文档「180+ 国家/地区」 | 指标不达标 | 补充真实司法辖区至 224 条 / 218 个辖区 |
| 14 | 前端模板误用未定义变量（`nodeTags`、`linkPreview.from`） | 页面运行时渲染报错 | 由视图自查发现并修复 |
| 15 | 报告列表缺少时间筛选、预警无处置接口 | 前端功能不可用 | 补齐 `start/end` 筛选与 `POST /compliance/alerts/<id>/handle` |
